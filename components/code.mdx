## Overview

TradeBotX uses **APScheduler** to run three background jobs automatically. All jobs are **NSE-calendar aware** — they skip weekends and NSE holidays.

```
APScheduler (BackgroundScheduler, IST timezone)
├── Job 1: Pre-Market Scan   — 08:30 IST daily (on trading days)
├── Job 2: Signal Scanner    — Every 5 min (09:30–15:20 IST)
└── Job 3: Portfolio Update  — Every 5 min (all day)
```

<Callout kind="alert">
  The auto-scanner is **disabled by default** (`"enabled": false` in `config.json`). Enable it explicitly and start with small position sizes before scaling up.
</Callout>

## Job 1 — Pre-Market Scan (08:30 IST)

Runs before market opens every trading day:
1. Fetches stocks from custom watchlist or NIFTY 50 index
2. Screens for RSI extremes, volume spikes, price gaps
3. Runs full 13-agent LLM pipeline on top 5 flagged stocks
4. Writes results to `morning_report.json` for the dashboard

**Configuration:**
```json
{
  "scheduler": {
    "enabled": true,
    "scan_time_ist": "08:30",
    "watchlist_source": "index",
    "index_name": "NIFTY 50",
    "max_stocks_to_analyse": 5,
    "only_analyse_flagged": true
  }
}
```

**Output — `morning_report.json`:**
```json
{
  "started_at": "2026-05-03T08:30:00+05:30",
  "finished_at": "2026-05-03T09:05:30+05:30",
  "screened_count": 50,
  "flagged_count": 5,
  "results": [
    {
      "ticker": "RELIANCE.NS",
      "decision": "BUY",
      "confidence": 4.5,
      "entry_price": 2850,
      "stop_loss": 2750
    }
  ]
}
```

**Manual trigger:**
```bash
curl -X POST http://localhost:8000/api/scan/morning
```

## Job 2 — Intraday Signal Scanner (Every 5 min)

The auto-trading engine. Runs every 5 minutes between 09:30 and 15:20 IST on trading days.

**Scan cycle:**

<Steps>
  <Step title="Batch LTP fetch" icon="download" title-type="p">
    One Upstox API call fetches live prices for all 50 NIFTY stocks simultaneously.
  </Step>
  <Step title="Score all 50 stocks" icon="bar-chart-2" title-type="p">
    `technical.py` computes 9 indicators using cached daily candles (60-min TTL) and fresh 5-min bars. Each stock gets a composite score 0–1.0. Total time: under 1 second.
  </Step>
  <Step title="Auto-entry" icon="trending-up" title-type="p">
    Score > 0.65 → enter paper trade (subject to: daily loss limit, position count ≤ 3, position size ≤ 5% capital). Logs: `AUTO BUY: INFY 10 shares @ ₹1850 (score 0.72)`.
  </Step>
  <Step title="Auto-exit checks" icon="trending-down" title-type="p">
    For each open position: score < 0.35 → SELL; price ≤ stop-loss → SELL; price ≥ target → SELL; trailing stop triggered → SELL; 15:20 IST → force close all.
  </Step>
  <Step title="Portfolio update" icon="database" title-type="p">
    `paper_portfolio` table updated: capital, daily P&L, win/loss counts, circuit breaker status.
  </Step>
</Steps>

**Configuration:**
```json
{
  "scanner": {
    "enabled": true,
    "interval_minutes": 5,
    "index": "NIFTY50",
    "buy_score_threshold": 0.65,
    "sell_score_threshold": 0.35,
    "max_auto_positions": 3,
    "position_size_pct": 3.0,
    "force_close_time": "15:20"
  }
}
```

**Typical trading day:**
```
08:30 IST — Pre-market scan runs (LLM analysis on 5 flagged stocks)
09:35 IST — Scanner activates, Scan 1: INFY score 0.72 → AUTO BUY 10 shares @ ₹1850
09:40 IST — Scan 2: RELIANCE score 0.71 → AUTO BUY 5 shares @ ₹2850
09:45 IST — Scan 3: INFY price ₹1900 (TP hit) → AUTO SELL, P&L +₹500
...
15:20 IST — Force close: SELL all open positions at market
Daily P&L: +₹1,250 (+1.25%)
```

curl http://localhost:8000/api/scanner/status          # Check state

`top_scores` returns the top 5 stocks by signal score on the last scan. This is the primary diagnostic tool for understanding why the bot is or isn't trading — if all top scores are below `buy_score_threshold`, no trades will happen regardless of how long you wait.

## Job 3 — Portfolio Update (Every 5 min)

Keeps P&L fresh without waiting for a trade to execute:
1. Fetches latest LTP from Upstox for all open positions
2. Recalculates unrealised P&L
3. Checks SL/TP for dashboard alerts
4. Monitors daily loss limit circuit breaker

Runs all day (including post-market) so the dashboard always shows current values.

## Data Validation — `candle_validator.py`

Before any indicator runs on a stock, `candle_validator.py` checks the raw OHLCV data. Stocks that fail validation are skipped — no signal is computed, no trade is entered.

| Check | Rule | Why |
|---|---|---|
| Sufficient history | ≥ 50 daily bars required | MACD needs 26, RSI needs 14 — need buffer |
| Valid OHLC | `High ≥ Low` on every bar | Corrupt feed detection |
| No extreme gaps | Price gap < 10% between bars | Detects stock splits / bonus issues |
| Non-zero volume | Volume > 0 on all bars | Prevents division-by-zero in volume ratio |

```python
from candle_validator import validate_candles

candles = await get_cached_daily_candles(client, symbol)
if not validate_candles(candles):
    logger.warning(f"SKIP {symbol}: failed data validation")
    continue                             # silently skipped before → now explicitly logged

score = compute_signal_score(candles, intraday_bars)
```

<Callout kind="info">
  Previously, stocks with bad data silently produced garbage scores and could trigger incorrect trades. Now they are detected and skipped with a log entry explaining why.
</Callout>

## Decision Logging

Every scan cycle now logs the reason a trade did or did not happen. Previously, most non-trade decisions were silent.

```
[SCAN] INFY.NS — score 0.72 → AUTO BUY 5 shares @ ₹1850 (score > threshold 0.65)
[SCAN] TCS.NS  — score 0.61 → HOLD (below threshold 0.65)
[SCAN] HDFC.NS — score 0.68 → SKIP: max positions (3) already open
[SCAN] SBIN.NS — score 0.71 → SKIP: daily loss limit active (circuit breaker)
[SCAN] WIPRO.NS — SKIP: failed data validation (insufficient history: 41 bars)
[SCAN] RELIANCE.NS — score 0.41 → EXIT open position (score < sell threshold 0.35)
```

This creates a full decision trail in the logs, making it easy to diagnose why the scanner was or wasn't trading on any given day.

## NSE Market Calendar

All jobs use `nse_holidays.py` to skip non-trading days:
- Market hours: **09:30–15:20 IST**, Monday–Friday
- Pre-market scan runs at **08:30 IST** (before open)
- No trading on weekends or NSE holidays (Holi, Diwali, Good Friday, etc.)

```python
from nse_holidays import is_trading_day, is_market_open

if not is_trading_day(today):
    logger.info("No trading today — weekend or holiday")
    return
```

## API Cost per Day

Cache TTL was reduced from 60 minutes to 15 minutes. This increases candle refresh API calls but all totals remain within the Upstox 1,000/day limit:

```
Morning scan (08:30):      ~15 API calls
Signal scanner (5 min):    ~5–10 calls/scan × 24 scans = ~300 calls
Candle cache refreshes:    ~4× more frequent (15-min TTL vs 60-min) = ~80 extra calls
Portfolio update:           ~1 call/5 min × 288 = 288 calls
Total: ~400–700 calls/day  (within Upstox 1,000/day limit)
```

## Troubleshooting

| Issue | Fix |
|---|---|
| Morning scan never runs | Check `logger.info("Scheduler started")` in startup logs |
| Scanner runs but no trades | Check logs for `SKIP` reasons — position limit, score below threshold, data validation failure |
| `"enabled": false` in config | Set to `true` in `config.json` and restart |
| "Scan already running" warning | Previous scan still in progress — normal if stocks are slow |
| `SKIP: failed data validation` | Stock has < 50 bars or bad OHLC — expected for newly listed stocks |
| Duplicate jobs | Check `add_job()` calls in `api_server.py` — remove duplicates |
| Force close not happening | Verify `"force_close_time": "15:20"` in config.json |
| No trades on holiday | Expected — `nse_holidays.py` blocks trading on NSE holidays |
